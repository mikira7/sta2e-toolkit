TNG chat cards

Three concepts for the lcars-tng era: the Working Results task card, the damage cards (ship and ground) and the smaller cards (Confirmed, Sensor Contact, Hazard Entry). Each concept is one frame used by every card, with the card type given by the frame colour: orange for tasks, red for damage, blue for sensors, gold for hazards. Cards are shown at Foundry's chat sidebar width. Every colour comes from the lcars-tng tokens plus the classic TNG pastels (tan, lilac, peach, blue). Antonio stands in for the LCARS lettering; the live cards currently use Arial Narrow.

Concept A · the classic TNG panel

Elbow Sidebar

A sidebar of numbered blocks runs down the left. It sweeps through rounded elbows into a title bar at the top and a matching bar at the bottom, with the title in the gap. Readouts are plain rows with bright numbers, the result is a full-width pill, and the keys are full pills with the label in the lower right. This is the nearest to the existing TNG frame (spine plus bar), so it would be the smallest change.

Concept B · the Enterprise-D console readouts

Bracket Console

Open brackets sit at the four corners, with the title centred in the gap of the top bar and segmented side arms between them. Each number is a horizontal gauge with its value beside it, so a glance shows how close a roll came. Dice sit in stadium-outlined strips. The keys are a two-column keypad, each key rounded on its outer end only. The layout is symmetrical and more decorative than A, and the gauges take more height.

Concept C · the LCARS menu screen

Menu Rail

A thick header bar carries the title in black lettering. It sweeps round a corner into a rail down the right edge, and the card's keys are stacked in that rail, so the buttons form part of the frame. A card with no buttons keeps the rail as numbered blocks. Readouts are rows with a half-pill tag on each label. This is the boldest of the three and the most like a real LCARS screen. The cost is width: the readout column loses about 90px.

Notes for building any of these

  • The working card would follow the TOS/TMP route: a task-card-tng.js skin built from the same skinView, keeping the DOM contract (.sta2e-working-actions, .sta2e-card-die dice, button classes, data-*). The other cards would get a new branch in lcarsChatCard in place of the current top/bottom-bar frame. Their bodies are already TNG-styled, so no tosifyBodyHtml-style pass is needed; the readout rows shown here would come from restyling those bodies.
  • Every key is a filled LCARS key, so it would carry data-filled="1". The armed look shown (black with a yellow outline and ▶) is what _armCardSelection already does to a filled key, so arming would not need a new code path. All radii live in CSS, as the no-inline-border-radius rule requires.
  • A and B put the reroll tray below the key grid, as today. C puts the keys in a narrow rail, so the tray appended to .sta2e-working-actions would need to span the full card width below the rail, and the Momentum spend panel (injected before the controls) would have to land in the readout column. C is the only concept that needs layout work beyond the frame.
  • The concave corners are the same radial-gradient fillets the current task-card frame uses (A, C). B gets them from a border elbow instead: the inner radius is the outer radius minus the border width.
  • Antonio is a Google font under the SIL OFL. Shipping it would mean bundling the files, as fonts/tmp/ does; otherwise it falls back to Arial Narrow.
